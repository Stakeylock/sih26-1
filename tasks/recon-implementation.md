## UI purposes

Analysis: compare current case evidence with explicit hypothetical assumptions; primary action is running/saving a scenario. The graph and tables show the same facts, never separate risk formulas.

Inspection planning: assign eligible available experts to a case and identify conflicts; primary action is a versioned reservation. Replace the simple unstructured visit schedule input with the planner while preserving legacy visits.

Policy administration: review a source-backed draft and its impact; primary action is publishing/adopting the reviewed version. Extend the notice registry rather than adding unsupported statutory promises.

Operations: inspect actual queues, attempts and readiness; primary actions are scoped assignment/retry/recovery requests. No decorative dashboard metrics or fictional deliveries.
